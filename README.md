# 车间知识图谱建图工作台

一个面向制造业设备维修知识管理的 Vue 3 交互式演示。它用一条模拟维修工单，展示从领域概念定义、候选实体与关系抽取，到质量筛选、专家审核、形成可追溯知识图谱的完整思路。

> 这是一份用于课程讲解、方案沟通和方法演示的前端原理 Demo，不是生产系统、论文算法复现，也不连接真实工厂设备或业务系统。

## 一眼看懂

传统维修经验常分散在设备手册、工单、共享盘和员工个人经验中。这个演示说明如何把这些信息整理成结构化知识，同时避免“模型说了就算”：模型只提出候选，规则负责拦截结构问题，设备专家确认事实，知识关系保留证据、适用范围和审核状态。

```text
维修工单/设备资料
        ↓
定义领域本体与关系边界
        ↓
LLM 辅助提出实体、关系和原文证据（演示交互）
        ↓
别名/设备匹配 + 置信度排序 + 规则校验 + 负例检查
        ↓
设备专家审核、确认或拒绝
        ↓
形成带来源、范围、时间和审核状态的知识图谱
        ↓
后续检索与维修辅助（本 Demo 不实现在线检索服务）
```

## 页面能演示什么

### 1. 定义本体：先约定知识的“语法”

界面展示设备、部件、故障、原因、措施、结果等实体类别，以及它们允许建立的关系。还展示机型、工况、时间、来源和审核状态等属性。

本体不是术语词典，而是对业务语义的约束：什么可以称为故障，哪些关系成立，需要附带哪些条件。先定义边界，再让模型提出候选，可以减少概念混用和关系乱连。

### 2. 抽取候选：模型提供线索，不直接写入知识库

演示者可以修改一条示例维修工单，并点击“运行 LLM 候选抽取”。当前页面的按钮仅触发本地演示状态，不会请求真实大模型，也不会对输入文本执行真实 NLP 推理。

页面用候选抽取的概念说明：从工单文本中识别嵌套实体、故障现象、可能原因、处置措施和结果，并尽量保留对应的原文证据。实体识别之后仍需进行实体对齐、语境判断和事实核验。

### 3. 过滤校验：置信度是排序信号，不是真实性证明

拖动阈值可观察候选关系的复核优先级。演示同时提示几类常见检查：

- 类型与关系是否符合本体约束；
- 设备型号、设备 ID、时间和来源是否匹配；
- 是否存在否定、假设、历史描述或非故障语境；
- 是否出现“提到故障词，但并没有发生故障”的负例；
- 低置信、资料冲突或证据不足时，是否进入人工复核。

提高阈值可能减少一部分低置信候选，也可能漏掉真实知识。具体阈值应使用领域标注集评估，不能把界面中的百分比直接当作经过校准的概率。

### 4. 专家审核：关键事实由懂设备的人确认

每条候选关系都可以确认入图、暂不采纳或撤销审核。高置信度不等于事实正确；涉及故障因果、维修有效性、设备适用范围或安全操作时，应由具备相应职责的人员核验。

### 5. 形成图谱：节点和关系都应能回到证据

点击图谱节点可查看类型、来源证据、适用范围及审核状态。真实应用还应记录资料版本、设备型号、有效时间、审核人和变更版本，支持后续核查与更正。

## 演示案例

页面内置一条虚构的教学示例：

> 机器人第二轴减速机轴承温度异常，设备报警停机。检查发现润滑不足，补充润滑后设备恢复。

从这段文字中，页面展示“机器人第二轴—减速机轴承—温度异常—润滑不足—补充润滑—设备恢复”等节点，以及“包含部件、出现现象、关联原因、对应处置、处置后结果”等关系。

该文本、工单编号、置信度、审核状态和图谱均为演示数据，不对应真实企业、设备、人员或维修事件。尤其要注意：单条工单里同时出现“温度异常”和“润滑不足”，并不能单独证明普遍因果规律；入图时应保留“记录原因”与“已验证因果”的区别，以及适用设备和工况。

## 推荐的建图方法

1. **领域本体先行**：由业务和设备专家确定概念、关系、属性和边界。
2. **权威数据优先**：设备 ID、型号、报警码、时间戳等优先取自主数据或业务系统，而不是依赖模型猜测。
3. **模型抽取候选**：LLM 可辅助识别嵌套实体、关系和证据片段；输出先进入候选区。
4. **实体对齐与语境识别**：处理简称、别名、同名部件、否定表达、假设描述和历史事件。
5. **规则与质量门**：检查数据结构、关系约束、来源、设备匹配、冲突和置信度。
6. **专家审核、版本化与反馈**：审核后再发布；保留修改记录，将纠错样本纳入评估和后续改进。

知识图谱的准确性不是由某一个“最强模型”单独决定的，而是由数据质量、领域定义、证据定位、实体对齐、规则校验、人工审核和持续评估共同决定。图谱结构自洽不代表现场事实正确。

## 质量评估建议

若将方法用于真实项目，建议分层评估，而不只展示图谱效果：

- **抽取质量**：实体与关系的 Precision、Recall、F1；按设备类型、故障类型和文本来源分层统计。
- **证据质量**：关系能否定位到原始工单片段、手册条款或权威字段。
- **语境质量**：是否正确区分否定、未发生、疑似、历史故障和已确认故障。
- **实体对齐质量**：同一设备或部件能否正确归一，错误合并和重复建点是否可控。
- **审核效果**：专家采纳率、驳回原因、复核工作量及审核一致性。
- **业务效果**：故障确认时间、工单首次完整率、平均修复时间（MTTR）、重复故障率等；需设定基线和统计口径。
- **安全与追溯**：访问是否按岗位授权，版本是否可回退，关键建议和审核过程是否留痕。

阈值、指标和发布标准必须用目标企业的代表性数据集验证。未经评估，不应将演示中的分数或状态当作实际系统性能。

## 如何运行

### 直接打开

使用最新版 Chrome 或 Microsoft Edge 打开 `index.html`。页面通过 CDN 加载 Vue 3.5.13，因此首次打开需要网络连接。

### 使用本地静态服务器（可选）

可以用任意静态文件服务器将本目录作为站点根目录，然后在浏览器访问对应地址。项目没有后端服务、数据库、构建步骤或 npm 依赖。

## 演示操作路线

1. 在“定义本体”查看实体类型、关系约束和关键属性。
2. 点击“抽取候选”，编辑示例工单并运行演示按钮。
3. 在“过滤校验”调整置信度阈值，检查候选关系、负例说明和规则校验边界。
4. 在“专家审核”逐条确认或暂不采纳关系。
5. 回到“形成图谱”，点击节点检查证据、适用范围和审核状态。
6. 使用“重置演示”恢复初始状态；也可以用顶部按钮逐步播放完整流程。

## 项目文件

```text
shopfloor-knowledge-graph-vue/
├── index.html   # Vue 3 单页应用、样式、示例数据与交互逻辑
├── preview.png  # 演示页面预览图

```

当前状态保存在浏览器页面内存中。刷新页面或点击“重置演示”会恢复初始示例；页面不会将数据写入服务器或持久化到本地存储。

## 技术说明

- **前端框架**：Vue 3.5.13 Global Build，通过 jsDelivr CDN 加载。
- **页面结构**：单文件 HTML；CSS、Vue 模板、示例数据和交互代码均在 `index.html`。
- **图谱呈现**：使用内嵌 SVG 绘制节点、关系边、箭头和状态；不依赖图数据库或图可视化组件。
- **当前交互**：流程切换、示例文本编辑、阈值调整、关系审核、节点选择和重置。
- **数据存储**：页面内存；不连接 API、数据库、MES、ERP、工控网或真实设备。
- **兼容性**：采用响应式布局，可用于桌面和窄屏浏览器；图谱在小屏上允许横向滚动以保证可读性。

## 重要边界与安全说明

- 本 Demo 不是 Bosch、SICK 或任何其他企业的内部系统、产品复刻或官方实现说明。
- 页面不实现论文中的 assInNNER、ANLM、INCT、CFM，也没有实现真实的实体识别、负样本召回、置信度校准或模型训练。
- 交互数据是静态教学样例；界面上显示的置信度仅用于解释筛选和审核流程。
- 不要将真实工单、图纸、配方、人员信息或企业敏感资料粘贴进公开托管版本。
- 若用于真实生产，应另行完成身份认证、最小权限、数据分级、网络隔离、模型评测、人工审批、日志审计、异常停用和恢复方案设计。
- 任何停机、复位、参数修改、联锁、安全许可或其他可能影响人员与设备安全的动作，都必须遵循企业现有授权、工艺和安全规程；本页面不执行此类操作。

## 可继续扩展的方向

- 让演示中的抽取步骤返回可解释的候选结构，同时保持“候选—审核—发布”的人工治理边界。
- 增加实体别名与设备主数据映射、原文证据高亮、冲突和否定语境样例。
- 增加知识版本、审批人、有效时间和撤回/回滚的交互演示。
